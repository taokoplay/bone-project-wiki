# BoneProjectWiki（项目知识库）

BoneProjectWiki 包含两个清晰分层的核心能力：

- **通用知识库（Knowledge base）**：由用户拥有的项目知识资产。支持笔记、资料、调研、决策、多媒体与各种自定义分类。Agent 仅在用户明确要求或当前任务直接相关时，方可整理、检索、读取、导入或更新。绝不主动摄取无关闲聊或把日常代码副产物当作知识落盘。
- **Agent 协作记忆（Agent memory）**：自动化的跨会话协作层。在轮次结算后，仅记录用户明确表达的偏好设定、关键修正或“记住这个”等持久事实。在下一轮对话开始时，以严格受限的篇幅注入上下文，作为参考依据，不可凌驾于用户的最新实时指令之上。

---

## 核心操作与规范

1. **环境初始化与快照**：
   - 知识库操作始终从 `snapshot` 开始，后续所有请求必须携带其返回的当前 `workspacePath`；
   - 切换项目后切勿复用旧路径。仅在当前项目尚未初始化且用户明确需要知识库时调用 `init`。
2. **知识检索与读取**：
   - 当用户询问具体的项目规范、设计或历史决策时，使用 `search`（支持全文关键词）或 `read`；
   - 检索与读取返回条目 ID、项目相对路径、状态及修订版本号（Revision）。文档另有稳定的 `recordId`，改名和移动后仍保留；读取原文使用 `{action: "read", recordId, section: "knowledge"}`。旧 `id` 仍兼容，无歧义时可定位；冲突时改用明确的 `recordId`，不可猜测原文。
3. **内容保存与更新**：
   - 使用 `save` 保存 Markdown 文档，支持标题驱动物理重命名；
   - 更新文档时，必须传入 `id` 和从 `read` 获得的 `expectedRevision`，若发生冲突需先核对最新内容；
   - 严禁随意删除非记忆类数据，归档条目请将 `status` 设为 `archived`。
4. **外部文件与多媒体**：
   - 知识库原生支持识别纯文本、Markdown、Word（`.docx`）、WPS（`.wps`, `.et`, `.dps`）、PDF、Excel 表格、图片及音视频；
   - 原型预览采用安全沙箱隔离，不连接外网，防范任意外部代码注入。
5. **记忆遗忘与个人偏好**：
   - 用户要求遗忘某条记忆时，在核实目标记忆 ID 后调用 `forget`；
   - 用户的私有偏好通过 `preferencesSave` 存入插件独立安全存储，不随知识库导出泄漏。

## 用户要求记住上文时

“记录到记忆中”“把刚才的开发规范记住”等表达是保存指令，不是要保存的事实正文。结合当前对话识别对象，提炼用户确认的具体事实，保留来源文档路径、适用项目和必要的限定条件。没有足够上文时说明无法确定内容，切勿凭空补写。

通过 `project_wiki` 执行 `snapshot`，使用返回的 `workspacePath`；尚未初始化时先 `init`。先搜索相关文档与记忆以避免重复。简单偏好使用 `save`，参数为 `kind: "memory"`、`category: "memory"`，标题描述具体事项，`content` 写具体事实，`source` 写来源；只有用户确认的事实才使用 `status: "confirmed"`。

不可用修改根目录 `MEMORY.md` 代替插件记忆写入。工具确认写入成功后才报告成功与返回路径；工具不可用或保存失败时明确说明尚未记录。排除凭证与敏感个人信息，不自动把助手猜测当成用户确认的事实。上下文只给全文入口时，必须先读取完整记忆，并核对来源文档的最新版本，不可把标题当成完整规则。

## 重要规则与业务知识

重要规则、业务流程、适用条件及例外需要独立主题文档。使用 `remember`，传 `kind: "document"`、知识库 `category`、`status: "confirmed"`、`title`、完整 `content`、不超过 800 字符的 `summary`、不超过 240 字符的 `readWhen` 和 `source`。更新前先 `read`，携带文档 `recordId` 及 `expectedRevision`。完整规则只维护在主题文档中；摘要不能替代执行前的原文读取。

该操作先核验文档落盘，再建立或更新记忆关联。只有返回 `linked: true` 才能报告完整成功。若 `linked: false`，说明文档已保存但关联未完成；使用返回文档的 ID、修订版本和相同摘要重试，不要重复新建文档。

关联状态为 `current` 时可参考短摘要；`stale` 表示正文变化，需读取当前文档并通过 `remember` 更新摘要。`draft`、`archived`、`missing`、`unreadable` 或 `ambiguous` 不提供旧摘要，必须说明状态，不可凭空补全。标题和目录变化不等于规则变化，稳定关联仍可定位当前原文。

用户仅询问或查看资料时，不主动整理写入知识库。不得自动把助手推测确认为业务规则。公开介绍、摘要与交付材料避免个人绝对路径、用户名、凭证及本机打包位置；来源使用公开仓库链接或必要的项目相对引用。

## 按任务使用记忆

- `status: "draft"` 的记忆是候选，保留在面板和显式读取中，不进入自动或手动上下文；仅将用户已确认的事实标为 `confirmed`。
- `save(kind: "memory")` 和 `remember` 可传 `scopePaths`，最多 16 个项目相对路径；空数组表示当前项目。更新时省略则保留原范围，不能把模块约定扩大成全局规则。
- `importance: "core"` 仅用于明确重要、可复用的规则，在适用范围内保留有限预算；其余保持普通优先级。不要把所有记忆都设为核心。
- 手动检索上下文传 `context` 的 `query` 和可选 `paths`。限定范围的记忆只有在任务明确出现匹配路径时才适用；缺少路径时先核对目标模块，不猜测范围。
- 旧的相关规则可以优先于新的无关记录。当前实现为本地关键词匹配，同义词或隐含任务仍可能需要显式搜索。
